# Genyx 0.4.0 — Commercial integration laboratory

## Verified prior baseline

The CRM candidate at 7103498 passed [CI](https://github.com/Holger2005/genyx/actions/runs/45940996473)
and [CodeQL](https://github.com/Holger2005/genyx/actions/runs/45940996453).

- 37 unit tests passed.
- 100 percent coverage of the selected domain/application code only.
- Local CLI smoke test passed in the isolated synthetic database.
- All 20 laboratory Lighthouse measurements met the numeric budgets in that run.
- Both homepages transferred 474386 decoded script bytes in the browser smoke test.
- Zero vulnerabilities reported by npm audit at that time.

The prior n8n test webhook was reported successful by the operator locally.
This does not certify the later bridge, production hosting or real-data handling.

## Candidate scope

- Bilingual portfolio, six service categories and availability-gated SaaS catalog.
- Project preparation draft, 30-minute consultation information, optional public
  Google Calendar and WhatsApp links.
- Local n8n test webhook, synthetic SQLite CRM CLI and authenticated response-validated
  operator bridge. No real lead intake, public admin UI or production persistence.
- Bilingual prototype privacy notice, not a final legal policy.

No dependency versions or lockfile resolutions have changed for this release.
The package version and root lockfile version are updated to 0.4.0.

## Automated release gates

CI on Node 22 and 24 checks architecture, lint, formatting, types, unit coverage,
build, CRM CLI and bridge contract. Node 24 additionally checks Chromium,
HTTP security headers, responsive layout and absence of public CRM/admin/intake
routes. The browser smoke test is not an exhaustive security assessment.

Lighthouse 13.6.0 now produces 22 reports: three mobile home runs per language,
one desktop home run per language, and mobile audits of projects, Genyx case,
services, products, inquiry, consultation and privacy in both languages.

- Performance and accessibility scores at least 95.
- LCP at most 2500 ms, CLS at most 0.1, TBT at most 200 ms.
- At least two of three independent mobile home samples must meet every numeric
  budget; every sample must meet accessibility and CLS. Other pages must pass
  their single-run gates. All results, including outliers, are retained.
- Best practices and SEO scores recorded, no SEO threshold while noindex is active.

Laboratory metrics are not field INP, accessibility certification or production
performance guarantees. The temporary pinned Lighthouse CLI dependency graph is
not part of the application lockfile.

## Separate commercial launch checklist

- [ ] Confirm an approved hosting plan permits commercial use and meets cost requirements.
- [ ] Verify real Calendar booking link and authorized WhatsApp business number.
- [ ] Review public identity, external portfolio media rights and service descriptions.
- [ ] Define data controller, privacy notice, contact channel, retention and deletion.
- [ ] Implement production authentication, authorization, abuse protection and durable
  storage before enabling any real lead intake.
- [ ] Validate HTTPS, HSTS, production CSP, backups and incident response.
- [ ] Review real devices, keyboard navigation, screen readers and field performance.
- [ ] Approve commercial publication and only then consider enabling search indexing.

The v0.4.0 release is a technical milestone. It is not authorization to process
customer data, publish a commercial site or deploy the local laboratory online.
